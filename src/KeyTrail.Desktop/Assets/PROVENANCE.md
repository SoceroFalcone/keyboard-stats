# Asset provenance

KeyTrail.ico is an original geometric application mark generated by `scripts/create-icon.ps1` using Windows System.Drawing: three rectangular keycaps and a spacebar on a rounded pine background. It contains no third-party imagery or generated illustration. Sizes: 16, 24, 32, 48, 64, 128, 256 pixels.

Interface graphics use data-driven WPF controls and original artwork. System fonts are Segoe UI / Microsoft YaHei UI, supplied by Windows.

V1.5 adds `Keyboard/keyboard-neutral.png`, generated from the user's keyboard photograph with the built-in image_gen tool on 2026-11-15. Native transparent size is 2172 × 724; the app decodes it at 1280 pixels wide. It retains the pictured no-numpad layout and molded cap/skirt appearance, removes RGB illumination, and leaves all legends blank for native, correctly mapped labels. Exact prompt is embedded and retained beside the asset; `Keyboard/provenance.json` records the reference and interpretation. The user photo remains a development reference under `artifacts/input-layout/reference`, not a shipping asset. No CLI image-generation fallback was used.

V1.5 reuses the V1.4.1 mouse raster without editing or mirroring it. The app applies one frozen rotation to the image and hit regions together, crops only the surrounding layout space, and decodes at 640 pixels for the smaller paired placement. No duplicate rotated bitmap is retained.

The shipping V1.4.1 asset is `Mouse/mouse-viper-neutral.png`, generated with the built-in image_gen tool on 2026-11-15 using official Viper V4 Pro images from the user's requested page as references. Exact source URLs and the complete prompt are in `Mouse/provenance.json`; the prompt is also embedded in the PNG and retained in `Mouse/mouse-viper-neutral.prompt.txt`. The native transparent image has no logo. Five traced surface regions use its luminance for data-driven heat tinting. This is a generated visualization based on the reference product, not an official photograph or automatic hardware identification. No CLI image-generation fallback was used.

The user found that V1.4's original generated plate had its side buttons on the physical right. That image is no longer embedded in the application; it and its prompt/provenance are archived in `artifacts/mouse-realistic/source`. V1.4.1 shows the nose upper-left and heel lower-right, with both thumb buttons on the physical left. The reference product page is https://www.razer.com/tw-zh/gaming-mice/razer-viper-v4-pro . Official source images remain development references only under `artifacts/mouse-viper/reference`.

Razer Synapse's physical-location interaction pattern was the user's reference; official documentation consulted: https://dl.razerzone.com/master-guides/RazerSynapse3/Jugan-00000099-en.pdf (Mouse tab / Customize). The generated object does not identify the user's mouse model.
